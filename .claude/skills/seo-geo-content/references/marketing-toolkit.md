# 行銷工具組套用規則（網站內容）

**院長 2026-10-10 裁示**：「製作網站相關內容時，直接把以上工具應用，先依建議自行選擇，再由我核可。」

工具組全文：`internal/行銷工具組_30項_20261010.md`。合規判準仍以 `00` §4 為準；本檔只規定**何時用哪幾支、怎麼交付**。

## 一、適用範圍

| 適用 | 不適用 |
|---|---|
| 凡產出或改寫**可見文字**：模式 B 新頁、既有文章改寫、服務頁段落、最新消息／首頁公告說明段、首頁卡標題、title／description、可見 FAQ、醫師／作者頁、站外同步稿（GBP／FB） | 模式 A 四層補強（零可見文字）、純技術層（schema 結構、meta 結構、redirect、工具腳本）、`internal/` 文件 |

不需要院長每次指定工具——**session 依下表自行選**，交付時寫明選了哪幾支、為什麼。

## 二、內容類型 → 預設工具組合

| 內容類型 | 預設順序 | 備註 |
|---|---|---|
| 新衛教文章（模式 B） | 04 痛點 → 06 知識缺口 → 03 標題 → 07 CTA → 發布前檢核 | 涉及檢查／設備加 10 價值翻譯；與 `hook-structure.md` 並用（04＝選題、06＝開場） |
| 服務頁新增或改寫段落 | 01 優勢 → 10 價值翻譯 → 13 疑慮（FAQ）→ 22 服務說明 → 發布前檢核 | 涉及費用或方案時加 21 促銷避雷 |
| 最新消息／首頁公告 | 05 真實時程 → 17 瘦身 → 27 語調 → 發布前檢核 | 門診異動公告仍以 `clinic-schedule` skill 為主流程，工具只用於說明段文字 |
| 既有文章改寫 | 09 爭議安全 → 28 同理心（視需要）→ 17 瘦身 → 發布前檢核 | dateModified 依 R4 判，與工具無關 |
| title／description／卡標題 | 03 標題（或 18 公式）→ 17 瘦身 | description ≤80 字 |
| 可見 FAQ 題組 | 13 疑慮 → 19 受眾（多族群時） | FAQ 只放頁面答得出來的題目（09-25l） |
| 醫師／作者頁 | 08 信任證據 → 23 品牌形象 | 師承客觀陳述 |
| 站外同步稿（GBP／FB／IG／LINE） | 26 改編 → 發布前檢核 | 社群字數規則依工具組共同設定 |

**每批固定最後一步＝「共用發布前檢核提示詞」**，對照〈合規紅線〉8 條自審一次。

## 三、預設不用（院長明確要求才用）

- **20 價格改寫、24 PSA 商品卡**：公開管道零價格（§4-12），網站內容不適用。
- **02 煙霧測試、25 主旨實驗、30 MVP**：屬試驗規劃，不是產稿工具。
- **12／14 短影音、15 天賦雷達、16 訊息偏好、11 語調分析、29 系列規劃**：非網站頁面產出；院長要求時照工具組用。

## 四、網站情境下的調整

- 工具組的「社群 350–450 字、標籤 3–5 個」是社群預設，**網站頁面不套**；頁面長度與結構依 `content-generation.md` 模板。
- 工具要求產出多個候選（如 03 的 12 個標題、07 的 5 個 CTA）時，**不要全部塞給院長**：session 先選定 1 個推薦版放進頁面，另列 2 個備選在交付說明。
- 工具的「內部查核備註」寫進交付說明或 PR body，**不進頁面**。
- 與本站既有規則衝突時，本站規則勝（`00` §4、`02`、`anti-ai-tone.md`）。

## 五、交付格式（加在既有交付說明裡）

```
【本批套用工具】
- 選用：04 → 06 → 03 → 07 → 發布前檢核
- 理由：新衛教文章、題目來自家長常問的鑑別問題（06 適合「一定是 X 嗎？」型）
- 標題：採用 A「……」；備選 B「……」、C「……」
- 發布前檢核結果：與資料相符 N 項／需外部查核 N 項（列出）／缺少院內確認 N 項（列出）
```

**核可方式不變**：可見文字仍待院長逐字核可（走 PR 者 merge＝核可）。院長可改選備選版本或指定改用其他工具。
