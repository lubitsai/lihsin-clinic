## 四、請院長裁示（依建議順序）

### 四-1｜byline 的醫師名連到醫師介紹頁（78 頁）【建議做】

- 現況：「由**蔡宗儒院長**審閱・更新：2026年9月」——名字是純文字。
- 做法：**文字一字不改**，只把醫師名包成 `<a href="/team/dr-tsai.html">`（李醫師頁連 `/team/dr-lee.html`），樣式沿用 byline 裡既有的來源連結 class，不新增 Tailwind class。
- 效益：直接對應建議第 3 點；家長點一下就看得到學經歷，AI 也能從可見連結確認審閱者是誰（schema 已有 `reviewedBy`，但可見層沒有對應連結）。
- 風險：低。改的是連結外觀，可見文字不變；因為外觀有變，仍然送院長核可。

### 四-2｜byline 來源連結改成指向具體文件（60 頁、62 條）【建議做，分兩段】

- 現況例：`health/influenza.html`「參考**衛生福利部疾病管制署**季節性流感防治資料整理」連到 `https://www.cdc.gov.tw/`（首頁），同一頁的 schema `citation` 卻已經列了具體頁「流感速訊」。
- 做法：**錨點文字不改**，`href` 換成該頁 schema `citation` 裡已經列出的**同一機構**文件網址。可見連結和 schema 會指向同一份文件，建議第 4 點與「schema 忠實對應可見內容」一次處理。
- **第一段（48 條）**：同一頁 schema `citation` 已經有**同網域**具體網址可以直接對應的（疾管署、國健署、氣喘衛教學會全部，外加兒科醫學會 1 條）。
- **第二段（14 條）**：schema 裡也只有該機構首頁的——兒科醫學會 12、食藥署 1、感染症醫學會 1（兒科醫學會是 `W-CITEDOC` 登錄過的已知例外：「未查得對應深層文件，誤連比不連更糟」）。建議**維持原狀**，等查到對應文件再換，不硬連。
- ⚠️ 前置：本 session 對外連線被 proxy 擋（`cdc.gov.tw` CONNECT 403），**無法逐條確認網址現在還能開**。核可後要先用 firecrawl 或請院長抽點確認，再動手。

### 四-3｜FAQPage schema 與可見內容對應（776 題）【建議選 A】

| 量測 | 數值 |
|---|---|
| FAQPage 題數（77 頁合計） | 776 |
| 題目在可見層逐字出現 | **82（10.6%）** |
| 一題都不可見的頁 | **46 頁** |
| 有可見 `<details>` FAQ（雙載）的頁 | 3 頁：`index`（68 題 schema／18 可見）、`services/vaccination`（15／4）、`visit-guide`（13／11） |

- **為什麼這是問題**：Google 結構化資料指南要求標記的內容必須是使用者在頁面上看得到的；另外 Google 從 2023 年起只對少數政府與知名衛生機構網站顯示 FAQ 複合式結果，本站就算標了也拿不到那個版面。所以這 700 多題目前的實際作用是給 AI 檢索用，而代價是「schema 與可見內容不一致」。`00` 檔頭 09-13p 那批也寫過同一條：「Google 要求 FAQPage schema 內容必須在頁面上可見」。
- **選項 A（建議）｜重點頁雙載**：比照 `services/vaccination`（08-24 提案核可的做法），在重點頁加可見的 `<details>` 收合 FAQ，內容與 schema 同一份。第一批只做 `services/` 12 頁＋`news/` 2 頁（約 150 題）。每頁的可見題目清單另出逐字稿送核可；收合區預設關閉，版面幾乎不會變長。
- **選項 B｜schema 瘦身**：只保留可見層答得出來的題目，其餘刪掉。一致性最快達成，但會失去 AI 檢索覆蓋，也會推翻歷批四層補強的成果。
- **選項 C｜維持現狀**：不動。
- **連帶的規則題（建議一起定）**：往後模式 A 新增 FAQ schema 題目時，是否要求「**可見層已經答得出來**」才加？（09-13 腸病毒批就是這樣做的，但還沒寫成規則。）這會修改 `keyword-research.md` 四層補強的做法，所以要院長裁示。

### 四-4｜首頁剩下的兩處 schema 重複／用途不符【建議做，純技術層】

- `SpecialAnnouncement`「提供台南北區夜間與假日小兒科門診時段」：這個型別是設計給疫情等**緊急公告**用的，用來寫常態門診時段屬於用途不符；而且門診時間已經寫在 `#organization` 的 `openingHoursSpecification`，兩處都要維護，遲早會對不上。**建議刪除**。
- `MedicalCondition`「兒童氣喘」在首頁有兩個獨立節點（本批修改後的第 1722 行與第 2015 行附近），都沒有 `@id`。**建議合併成一個**（`alternateName` 取聯集），不減少資訊。
- 這兩項都只動 schema，但刪除型別屬於策略選擇，所以先問。

### 四-5｜4 頁 byline 日期與 `lastReviewed` 不一致【請裁示方向】

| 頁面 | byline（標籤「更新」） | schema `lastReviewed` |
|---|---|---|
| `health/child-chronic-cough.html` | 2026-05-12（顯示 2026年5月） | 2026-07-06 |
| `health/hpv-vaccine.html` | 2026-07-12（顯示 2026年7月） | 2026-09-01 |
| `health/mycoplasma-pneumonia.html` | 2026-09-10 | 2026-09-20 |
| `health/nasal-flu-vaccine.html` | 2026-09-08 | 2026-09-09 |

- 成因：都發生在 09-21g「byline『更新』跟著 `lastReviewed` 跳」的規則定案之前。
- 後兩頁顯示文字都是「2026年9月」，只差 `datetime` 屬性，可以直接對齊 `lastReviewed`。前兩頁要動可見月份（5 月→7 月、7 月→9 月）。
- 因為 `00` §4-9 有「不回溯」原則，**本批沒有動**。請院長裁示：四頁 byline 對齊 `lastReviewed`（建議，這是把兩個已存在的日期對齊，不是補一個沒發生過的審閱），還是維持現狀。

### 四-6｜`visit-guide.html` schema 說有醫師審閱，可見層卻沒有 byline【二選一】

- schema `author`／`reviewedBy`＝蔡醫師（T1 已修好懸空引用），但頁面上看不到任何審閱標示，不符合「schema 忠實對應可見內容」。

### 四-7｜三個服務頁補「比較或流程」段【等院長有素材再做】
