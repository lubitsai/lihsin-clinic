# 立欣診所 LINE 客服：部署操作步驟（Cloud Run）

照順序做即可。全程約 40 分鐘，**請選門診外的時段**。技術細節與版本紀錄在 `README_設定步驟.md`，這份只寫操作。

重點先講：
- 換的是**現有的 Cloud Run 服務**，Webhook 網址不變，LINE Developers 不用改網址。
- 先用 **pilot（測試模式）** 上線：一般家長看到的跟現在一樣，只有測試者會收到新回答；測完才切正式。
- 出問題 1 分鐘內可以退回原本的版本（第六步）。

---

## 第一步：準備（10 分鐘）

1. 下載最新的部署包 `立欣診所_LINE客服_X.XX_main-xxxxxxx.zip`。版本以檔名為準，用最新那包。
2. 打開 Google Cloud Console → 左上選單 → **Cloud Run**，在服務清單找到現在接 LINE 的服務，記下兩樣東西：
   - **服務名稱**（例如 `linebot`）
   - **區域**（例如 `asia-east1`）
3. 打開 LINE Developers → 診所的 Provider → Messaging API Channel：
   - **Basic settings** 分頁最下面：**Channel secret**
   - **Messaging API** 分頁最下面：**Channel access token (long-lived)**

   這兩串第二步會用到，**只貼在 Cloud Shell 裡、不要貼到任何聊天視窗**。

## 第二步：部署（Cloud Shell，15 分鐘）

1. Cloud Console 右上角點 **啟用 Cloud Shell**（`>_` 圖示），下方會開一個終端機。
2. 終端機右上 **⋮ → 上傳**，選第一步的 zip 檔。
3. 依序貼上以下指令（每行貼完按 Enter）。`<專案ID>`、`<服務名稱>`、`<區域>` 換成您的值：

   ```
   gcloud config set project <專案ID>
   python3 -m zipfile -e 立欣診所_LINE客服_*.zip lh && cd lh/line-helpdesk
   bash deploy_cloudrun.sh <服務名稱> <區域> --dry-run
   ```

   最後一行是**試跑**，只顯示會做什麼，不改任何東西。請確認：
   - 「目前上線版本」有抓到名稱（這是出問題時要退回的版本）
   - 「Webhook 網址（不會改變）」跟 LINE Developers 上的一樣

4. 確認沒問題後正式執行：

   ```
   bash deploy_cloudrun.sh <服務名稱> <區域>
   ```

   腳本每一步都會先問，輸入 `y` 才做：

   | 腳本問 | 怎麼回答 |
   |---|---|
   | 建立 Firestore 資料庫（第一次才會問） | `y`。這是轉專人案件清單用的資料庫，放在台灣區 |
   | 授予服務帳戶 Firestore 權限 | `y` |
   | 開啟 TTL 自動清理 | `y`。只清七天前的事件記錄，不影響案件 |
   | 請貼上 Channel access token／Channel secret（第一次才會問） | 貼上第一步的兩串，**畫面不會顯示**，貼完按 Enter |
   | 部署（BOT_MODE=pilot）？ | `y`，約 3～5 分鐘 |

   - 第一次部署，Google 可能會問要不要啟用 Cloud Build、Artifact Registry 等 API，回答 `y`。
   - 如果出現「此服務由 Cloud Functions 管理」之類的警告，**先回答 N 停下來**，截圖給我。

5. 看到「完成」就部署好了。資料夾裡會多一個 `rollback_command.txt`，是退回原版本的指令。

## 第三步：LINE 後台（10 分鐘）

1. **LINE Developers** → Messaging API → Webhook settings：
   - 按 **Verify**，應該顯示 Success。
   - 確認 **Use webhook**、**Webhook redelivery** 都是開啟。
2. **LINE Official Account Manager** → 自動回應訊息：
   - **關閉「最新門診異動」這組關鍵字回應**，改由程式讀官網公告回答。這一步一定要做，否則家長會同時收到舊圖和新回答。
   - 「流感疫苗資訊」「過敏氣喘諮詢」「減重營養諮詢」三組**保留**。
   - 「過敏氣喘諮詢」換成新的 4 張圖，依序是主視覺 → 哪些問題可以看 → 專診內容 → 檢測價目。每張卡的點擊連結見 `internal/line-oa/README.md`。
3. 員工手機的 LINE 官方帳號 App 要開啟聊天通知。

## 第四步：測試模式實測（15 分鐘）

1. **把員工加為管理員**：員工用自己的個人 LINE 私訊診所官方帳號，輸入 `/我的ID`，會收到一串 U 開頭、33 個字元的 ID。在 Cloud Shell 輸入：

   ```
   gcloud run services update <服務名稱> --region <區域> --update-env-vars ADMIN_USER_IDS=U開頭的ID
   ```

   有兩位以上時，ID 之間用英文逗號隔開，而且指令要改成這樣寫（多加 `^@^`）：
   `--update-env-vars ^@^ADMIN_USER_IDS=Uxxx,Uyyy`

   管理員同時也是測試者。
2. 用管理員的 LINE 逐項測，**全部打勾才進第五步**：
   - [ ] 問「診所電話」→ 一則電話回答
   - [ ] 問「我兒子呼吸困難怎麼辦」→ 立刻收到 119 訊息
   - [ ] 問「過敏原檢測多少錢」→ 四套組價格（4,000／5,000／7,000／10,000 元）＋但書
   - [ ] 點選單「診所資訊」→ 卡片的時間是 24 小時制（14:30–18:00）
   - [ ] 點卡片上「最新門診異動」→ 收到官網公告，或「目前沒有門診異動…」＋門診時間表。**沒有出現舊圖、沒有案件編號**
   - [ ] 點選單「醫師介紹」「流感疫苗資訊」「過敏門診」「減重門診」→ 各只收到一則回覆，沒有重複
   - [ ] 問「可以刷卡嗎」→ 收到待處理訊息和案件編號
   - [ ] 員工傳 `/客服 待處理` → 看得到上一題；在後台回覆後，傳 `/客服 結案 案件編號` → 收到「已結案」
   - [ ] 輸入「專人服務」之後再問「診所電話」→ 程式不回答（等真人回覆）；再輸入「孩子嘴唇發紫」→ **仍收到 119 訊息**
   - [ ] 傳一張圖片 → 自動轉專人
   - [ ] 用一支**不是管理員**的 LINE 問「診所電話」→ 和現在一樣（測試模式不影響一般家長）

## 第五步：正式上線

全部通過後，在 Cloud Shell 執行（不用重新部署，約 1 分鐘）：

```
gcloud run services update <服務名稱> --region <區域> --update-env-vars BOT_MODE=live
```

用非管理員的 LINE 再問一次「診所電話」，有收到新回答就完成了。請通知櫃檯：每天固定時段傳 `/客服 待處理` 查看待處理案件。

## 第六步：出問題時

- **新回答怪怪的，但服務正常**：改成 `BOT_MODE=off`（指令同第五步），新問答立刻停用，原本的卡片照常回覆。
- **整個壞掉**（例如 LINE 完全沒回應）：在 Cloud Shell 的 `lh/line-helpdesk` 資料夾執行

  ```
  bash -c "$(cat rollback_command.txt)"
  ```

  流量會切回部署前的版本。也可以在 Cloud Run → 服務 → 修訂版本 → 管理流量，把 100% 給舊版本。
- 退回舊版後，舊程式看不懂轉專人狀態，請人工確認 `/客服 待處理` 裡還沒結案的案件。

## 第七步：圖文選單加中間那一格（可另外找時間做）

1. 打開 Google Colab，新增程式碼儲存格，貼上 `internal/line-oa/current/line_menu_clinic_ready.py` 全文，執行。
2. 貼上 Channel access token（輸入時隱藏）→ 上傳 `rich-menu-8grid.jpg`（圖不用換）。
3. 核對列出的 9 個區域，最後一行應該是「官網首頁（中間品牌帶）→ https://lhpedclinic.com.tw/」，然後輸入 `發布`。
4. 重開手機 LINE 聊天室，9 個區域各點一次。
5. 把下載的 `line_menu_backup.json` 傳回來更新 repo。

## 第八步：穩定一週後（建議）

舊程式把 Token 直接寫在程式碼裡，舊版本的原始碼現在還留著明碼。確定不需要退回舊版後：

1. LINE Developers → Messaging API → Channel access token (long-lived) → **Reissue**。舊 Token 會立即失效，所以只能在確定不退回舊版之後做。
2. 在 Cloud Shell 更新 Secret，再讓服務重新讀取：

   ```
   read -r -s -p "新 Token：" v; printf '%s' "$v" | gcloud secrets versions add lh-line-channel-access-token --data-file=-; unset v; echo
   gcloud run services update <服務名稱> --region <區域> --update-env-vars TOKEN_ROTATED=$(date +%Y%m%d)
   ```

3. 傳一句「診所電話」，有收到回答就完成了。之後跑第七步的 Colab，要用新的 Token。
