院長對話上傳的三張 1254×1254 公告圖（早診／午診／晚診各一款，**無日期、可重複使用**），

| 檔案 | 尺寸 | 用途 |
|---|---|---|
| `images/social/registration-closed-morning.jpg` | 1254² | **母檔**（早診）：產限動版的來源，本身不發布 |
| `images/social/registration-closed-morning-story.jpg` | 1080×1920 | **實際發布**：FB／IG 限動（早診） |
| `images/social/registration-closed-afternoon.jpg` | 1254² | **母檔**（午診）：同上 |

| `images/social/registration-closed-evening.jpg` | 1254² | **母檔**（晚診）：同上 |
| `images/social/registration-closed-evening-story.jpg` | 1080×1920 | **實際發布**：FB／IG 限動（晚診） |

**為什麼要另產限動版**：限動畫布是 9:16，方形圖直接上傳會被上下補黑邊或左右裁掉字。
工具 `internal/tools/make_story_image.py` 把方形圖置中放在 1080×1920 上，
上下留白取圖**四個角落的平均色**往接縫漸層——晴天版得到淺藍、夕陽版得到橘、
夜晚版得到深藍，三款各自對得上，不必手動配色。

> **踩過的兩個雷（已寫進工具 docstring，不要再試一次）**：
> ① `--bg blur`（整張放大模糊填滿）取到的是圖的**中段米色文字框**，夜晚版會糊成土色、
> 和深藍天空對不上。
> ② `--bg edge`（邊緣像素往外拉伸）在這組圖上會把**上緣的綠色布條**和**下緣的米色資訊列**
> 拉成看得出字影的直向拖影。
> → 預設 `--bg solid` 是唯一在這三款上都乾淨的作法。

**版位安全區已確認**：公告圖落在 y 420–1500，IG 頂部頭像（約 250px）與底部回覆列
（約 250px）都蓋不到。

⚠️ **這三張刻意放 `images/social/`，不放 `images/notice/`**：
`images/notice/` 是官網 `#clinic-notice` 用的**當期**公告圖，受 SOP §一.6
「公告下架後一併刪檔、只留當期那一組」的清理規則管。這三張是**常駐重複使用的社群模板**，
放進 `notice/` 會在下一次清理時被誤刪。

⚠️ **這三張不要掛上官網公告區**：圖上寫「本日」但沒有日期，官網是持續存在的頁面，
掛上去等於每天都在說「本日停掛」。官網的當日公告仍走 `clinic-schedule` 既有流程
（帶日期的公告圖 ＋ `data-expires`）。

## 三、自動化規劃（待院長申請 token 後實作）

### 各載體可行性

| 載體 | 可行 | 端點 | 費用 |
|---|:--:|---|---|
| LINE 圖文選單切換 | ✅ | Rich Menu API（`/v2/bot/user/all/richmenu/{id}`） | 免費、不吃訊息量 |
| LINE 群發訊息 | ✅ | `POST /v2/bot/message/broadcast` | ⚠️ 見下方費用 |
| LINE VOOM／主頁貼文 | ❌ | **無公開發文 API** | 只能手動 |
| FB 粉專貼文 | ⬜ | `POST /{page-id}/photos` | **院長裁示不放，本專案不實作** |
| FB 限時動態 | ✅ | `POST /{page-id}/photo_stories` | 免費 |
| IG 限時動態 | ✅ | `/{ig-user-id}/media`（`media_type=STORIES`）→ `/media_publish` | 免費 |

### ⚠️ 為什麼不走 LINE 群發（院長 2026-09-14 已裁示走圖文選單）

LINE 群發**按觸及人數計費**。`00` 記錄的好友數為 **6,653**，等於**一次公告 6,653 則**：

- 輕用量（免費／200 則）→ 發不出去
- 中用量（NT$1,200／月、3,000 則）→ 發不出去，**且中用量不能加購**
- 高用量（NT$1,400／月、6,000 則，超出 NT$0.2／則）→ 一次就吃光月額度、再超 653 則

一個月發 3 次約 19,959 則，月費之外還要約 NT$2,800。
（月費為 2026-11-01 起的新價；在此之前中用量 800、高用量 1,200。）
**判斷**：一則「本日早診停掛」對 6,653 位好友來說絕大多數今天本來就沒要來，
花錢又擾民。圖文選單免費、不吃訊息量，家長開對話就看得到。

### 院長需要準備的（一次性）

1. **LINE Developers**：為 @lhpedclinic 建 Messaging API channel，取得 **channel access token**。
2. **Meta**：建一個 app、綁 **立欣診所粉專**與 **IG 商業帳號**，取得 **Page access token**
   （建議用 system user token，不會 60 天過期）。
   權限：`pages_manage_posts`、`pages_read_engagement`、`instagram_basic`、
   `instagram_content_publish`。
   > `pages_manage_posts` **即使不發貼文也還是要**——FB 限時動態同樣需要粉專的
   > CREATE_CONTENT 權限，不是只有動態牆貼文才用得到。
   > 自家粉專、院長本人是 app 管理員的情況，通常 **Standard Access 就能發、不必送 App Review**
   > （Advanced Access 是給「管理別人的粉專」用的）。**這點要實測確認，不要當成已知。**
3. token 一律填進 **GitHub Secrets**，⛔ 不得寫進 `.mcp.json` 或任何 commit（`CLAUDE.md` 架構約束）。

### 實作形狀

`internal/tools/publish_notice.py` ＋ 一個 `workflow_dispatch` 的 GitHub Actions workflow：

```
選診次（早／午／晚）→ workflow 同時發 FB 限動＋IG 限動＋切 LINE 圖文選單
                    → 回報三項各自的成功／失敗
```

- **圖從 `lhpedclinic.com.tw/images/social/…` 直出**——IG 要求公開 URL，本站本來就有。
  （這也是這批把圖放進 `images/` 而非 `internal/` 的原因之一。）
- **workflow 有手動按鈕**：院長在手機上就能自己按，不需要開 Claude session。
  診所忙翻的時候這比找 Claude 快。
- **必備 `--dry-run`＋一次確認才真送**：發出去收不回。
- **Meta 會拒絕已經發過的素材**，所以發限動前要複製一份帶時間戳的檔名再上傳。
- **撤除**：院長要求「當診門診時間結束就要撤除」，這不是 workflow 的一個附加模式，
  而是另一半的設計——**詳見 §四**。

### ⛔ 尚未解決的一件事

**LINE 圖文選單的素材還做不出來**——Rich Menu 是 2500×1686（或 2500×843）的**選單**，
上面有可點擊的分區。把它整張換成停掛公告會**蓋掉原本的預約／門診時間／看診進度按鈕**。
正確作法是做一張「上方公告橫幅＋下方維持原按鈕」的變體，**但這需要先看到目前那張選單的
版面與分區座標**。→ 請院長提供目前的圖文選單圖檔與按鈕配置，或 LINE 後台截圖。

## 四、撤除機制（院長 2026-09-14 補充要求：「當診門診時間結束就要撤除」）

### 4-1 撤除時刻表（由 `index.html` 的 `SCHEDULE` 推導）

| 停掛的診次 | 該診次結束 | **撤除時刻** | 為什麼 |
|---|---|---|---|
| 早診 | 平日 12:00／週六日 11:30 | **同左** | 下一個掛號窗口 14:30（週日 18:00），有充裕空檔 |
| 午診 | 週一～六 18:00（週日無午診） | **17:55** ⚠️ | **晚診 18:00 就開始收現場號**，撤晚了家長會以為整晚都不能掛 |
| 晚診 | 平日 21:30／週日 21:00（週六無晚診） | **同左** | 下一個窗口是明早 08:00，有充裕空檔 |

**午診那格是唯一沒有空檔的**：午診看診到 18:00、晚診掛號也是 18:00 開始，兩者貼在一起。
所以午診公告刻意提早 5 分鐘撤——寧可有 5 分鐘沒公告，也不要在晚診已經開始收號時
還掛著「停止掛號」。

⛔ **撤除腳本不得把上表的時刻寫死**。門診時間會變（情境 B），寫死就會在改班表那天
悄悄失準——而且失準的方向是「選單停在停掛畫面」。
腳本要從既有的單一事實來源讀：`index.html` 的 `SCHEDULE`／`EXCEPTIONS`
（`sync_schedule.py` 已經在做同一件事，解析邏輯可以沿用），
**單日特例 `EXCEPTIONS` 也要吃**——颱風那天整日休診，撤除時刻當然不是平常的 12:00。

### 4-2 各載體撤得掉嗎

| 載體 | 不撤會怎樣 | 撤除方式 | 必要性 |
|---|---|---|---|
| **LINE 圖文選單** | **永久停在停掛畫面**，隔天家長開 LINE 還看到「本日停止掛號」 | 切回原本那張 | ⭐ **最關鍵**，這是唯一不會自己消失的 |
| IG 限動 | 24 小時後自動消失 | `DELETE /{ig-media-id}` | 想準時撤就要刪 |
| FB 限動 | 24 小時後自動消失 | `DELETE /{story-id}`（⚠️ 需實測） | 同上 |

> **IG 限動可以刪**：Meta 的 Instagram Media 參考文件寫明
> 「Non-ad posts, stories, reels and entire carousel albums are supported for deletion」。
> **FB 限動的刪除端點我沒能親自查證**（本 session 的 egress 擋掉 `developers.facebook.com`），
> 依 Pages API 的一般規則推定可行，**列為實作時必須實測的項目，不要當成已知**。

### 4-3 設計：用「對帳迴圈」，不要用「一次性定時器」

⛔ **不要做成「發布時排一個 12:00 的鬧鐘」**——鬧鐘漏掉一次，選單就永遠停在停掛畫面。

✅ **做成每隔幾分鐘跑一次的對帳**：問 LINE「現在掛的是哪張圖文選單？」
（`GET /v2/bot/user/all/richmenu` 會回目前的預設選單 ID），
如果是停掛那張、而且已經過了本診次的撤除時刻 → 切回原本那張。

這個設計有三個好處：

1. **狀態存在 LINE 自己身上，不需要另外存檔**——不必 commit 狀態檔（也就不會每次發公告
   都觸發一次 Netlify build），不必用會被淘汰的 Actions cache。
2. **漏跑會自己補**：這一輪沒跑到，下一輪照樣會發現「選單還停在停掛狀態」並修正。
3. **手動介入不會打架**：院長自己在後台切回去了，對帳發現狀態已正確，什麼都不做。

IG／FB 限動同理：IG 有 `GET /{ig-user-id}/stories` 可以列出目前還活著的限動，
對帳時找出我們發的那則來刪，不必把 media id 存起來。

### 4-4 執行環境與它的誤差

**GitHub Actions `schedule` cron**（repo 是 public，**Actions 分鐘數免費、跑多密都不用錢**）。

⚠️ **但 GitHub 的排程是 best-effort**：尖峰時段常延遲 5～20 分鐘，偶爾整個跳過。
所以：

- 對帳掃描設在門診時段內每 5～10 分鐘一次（cron 最短間隔就是 5 分鐘），
  **靠密度和自我修復吃掉延遲**，不靠單次準時。
- **午診那格要把 cron 提早**：目標 17:55，cron 就設 17:40 起連續掃，
  這樣就算延遲 15 分鐘也還在 17:55 之前。

**如果院長要求分鐘級準時**，唯一可靠的作法是把對帳排在**我們自己控制的常駐主機**上——
也就是 `booking-system` 的 Docker 主機（加一個獨立的 cron job，**不動 booking-system 這個
應用本身**）。MainPi 是第三方服務、不是我們的機器，不能拿來排程。
**這是取捨題，等實作時院長裁示。**

### 4-5 官網若要一起做，現有機制不夠

目前官網公告的過期機制是 `data-expires`，**粒度是「日」不是「時分」**
（`data-expires` 當日仍顯示、翌日起隱藏）。
「當診結束就撤」需要時分粒度，等於要改 `#clinic-notice` 的那段 JS。
**本批不做**——這三張圖依第一節的判斷本來就不上官網。
真要做再另開一批，並且要注意 `sw.js` 對 HTML 走 network-first、不影響。
