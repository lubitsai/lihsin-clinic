# 10｜測試與驗收

上線前要能回答兩個問題：**「規則算得對嗎」**與**「人真的點得動嗎」**。
這兩件事由兩套測試分別負責，加上一個可以自己點的示範環境。

| | 驗什麼 | 怎麼跑 | 大約多久 |
|---|---|---|---|
| **單元／規則測試**（vitest） | 預約規則、額度、未到、班表、假日、權限判斷 | `npm test` | 20–30 秒 |
| **端對端測試**（Playwright） | 家長與櫃檯用瀏覽器實際點得動、看得到 | `npm run test:e2e` | 2–4 分鐘 |
| **示範環境** | 院長與櫃檯自己點過一遍 | `npm run demo` | 一次設定 |

兩套都跑：`npm run test:all`

## 一、示範環境（給人點的）

```bash
cd booking-system
npm run demo          # 重建示範資料庫、灌入班表與假資料
DATABASE_URL="postgresql://postgres@127.0.0.1:5433/lihsin_booking_demo" npm run dev
```

開瀏覽器：

- 前台（家長看到的）：<http://localhost:3000>
- 後台（櫃檯用的）：<http://localhost:3000/admin>

| 帳號 | 密碼 | 能做什麼 |
|---|---|---|
| `admin` | `lihsin-admin-2026` | 全部，含系統設定與員工管理 |
| `counter1` | `lihsin-staff-2026` | 櫃檯日常：代約、報到、改期、取消、匯出 |
| `dr-tsai` | `lihsin-doctor-2026` | 只看自己的預約，不能代約／改期／匯出 |

示範資料包含：今天幾筆等待報到與已報到、一筆帶同行家人、未來幾天的預約、
一位累計 3 次未到而被自動限制的病人、以及一筆單日停診公告。

**驗證碼不會真的發簡訊**：測試環境會直接把 6 位數帶進欄位（伺服器終端機也會印）。
前台查詢可用示範病人：證件號 `A100000010`、生日 `2020-03-15`、手機 `0900000001`。

> ⚠️ `npm run demo` 用的是獨立資料庫（`lihsin_booking_demo`），不會動到正式資料。
> **正式上線請用全新資料庫只跑 `npm run db:seed`，不要跑 `db:seed:demo`。**

## 二、院長／櫃檯驗收清單

逐項點過，有問題的圈起來回報即可。

### 前台（家長）

- [ ] 首頁看得到今日門診、各診次現場掛號開始時間、近期門診異動
- [ ] 「立即預約」→ 選門診 → 選醫師 → 選日期 → 選時段 → 填資料 → 送出，全程順暢
- [ ] 送出前必須勾選個資告知同意，沒勾會被擋下
- [ ] 完成頁明確講出「還要到櫃檯報到才算掛號」
- [ ] 減重／過敏門診只出現蔡醫師；兒童發展篩檢的可選時段符合公告（週一僅下午）
- [ ] 「查詢／取消預約」用證件號＋生日＋手機驗證碼查得到，並可自行取消
- [ ] 隨便輸入一組不存在的證件號，訊息是中性的「查無符合的預約資料」
- [ ] 規則頁看得到 119 但書、疫苗但書、篩檢兩證件規則、個資告知

### 後台（櫃檯）

- [ ] `counter1` 登入後看得到今日總覽，示範預約都在
- [ ] 報到、改期、取消、標記未到都按得動，畫面即時更新
- [ ] 逾時未報到的那筆會標「報到逾時」（紅框）
- [ ] 搜尋病人找得到，病歷頁的證件號是遮罩的（看不到完整號碼）
- [ ] 匯出 CSV 下載得到，且檔案內證件號同樣遮罩
- [ ] 排班頁看得到週班表與示範的單日停診
- [ ] 改週班表時，若有預約會落在新班表外，**會先列出名單、班表不動**
- [ ] 系統設定頁的國定假日涵蓋範圍顯示到 2027-12-31

### 權限

- [ ] `dr-tsai` 登入後**看不到**匯出 CSV 與列印
- [ ] `dr-tsai` 進不了系統設定與員工管理
- [ ] `counter1` 進不了員工管理
- [ ] 未登入直接開 `/admin` 會被導回登入頁

## 三、自動化測試

```bash
npm test          # 規則引擎（不需要瀏覽器）
npm run test:e2e  # 前台＋後台，真的開瀏覽器點
npm run test:all  # 兩套都跑
```

E2E 每次執行會**重建**測試資料庫（`lihsin_booking_e2e`）再灌示範資料——測試會取消預約、
改班表，不重建的話跑第二次起點就不同，會出現「昨天過、今天不過」而程式其實沒變。

失敗時 Playwright 會留下截圖與可回放的 trace：

```bash
npx playwright show-report                 # 網頁版報告
npx playwright show-trace test-results/<失敗的測試>/trace.zip
```

### E2E 涵蓋的項目

**前台**：完整預約流程、首頁重點資訊、規則頁合規段落、查詢與自行取消、
查無資料的中性訊息。

**後台**：登入與錯誤訊息、未登入導回、今日總覽與報到、病人搜尋與證件號遮罩、
排班頁、國定假日涵蓋範圍、三種角色的權限界線（含直接打 API 網址也要被擋）。

> **為什麼權限那幾項要用瀏覽器測**：`npm test` 驗的是「函式會不會拒絕」，
> 但畫面上按鈕還在、連結還連得過去也是問題。實際上第一次跑 E2E 就抓到
> 醫師唯讀帳號看得到「匯出 CSV」按鈕（後端會擋、資料不會外流，但按了只會得到錯誤）。

## 四、開發模式的 CSP

`next dev` 的 React Refresh 需要 `'unsafe-eval'`，被 CSP 擋掉的話**整個網站不會 hydrate**：
畫面正常，但每一顆按鈕都沒反應（點門診類型停在步驟 1、登入鈕永遠 disabled）。
`next.config.ts` 已針對開發模式放寬，**正式建置維持嚴格設定**。

日後若把 CSP 收得更緊，記得先用 `npm run dev` 點一遍再交付——這個症狀很像「程式壞了」，
但瀏覽器主控台會直接寫出被 CSP 擋住。
