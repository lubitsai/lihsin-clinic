## 二、部署（A 完成後，約半天）

逐步指令見 `06-部署與備份.md`，這裡只列順序與檢核點。

1. **建 VM**：`asia-east1`（彰化）、`e2-medium`、Ubuntu 24.04、50GB、**保留靜態 IP**。
2. **鎖防火牆**：只開 80／443，SSH 改走 IAP，刪掉預設那條對全世界開放的 22。
3. **設 DNS**：`booking` A 紀錄 → 靜態 IP。**解析生效後**再啟動 Caddy（憑證申請需要網域先指得到）。
4. **裝 Docker**、取得程式碼、`cp .env.example .env` 並填入：
   - 三把密鑰各自 `openssl rand -base64 48`
   - `POSTGRES_PASSWORD`、`APP_BASE_URL=https://booking.lhpedclinic.com.tw`
   - 簡訊供應商帳密（B）、LINE 四組憑證（C）
5. **啟動**：`docker compose up -d --build` → `prisma migrate deploy`
6. **建資料**：**只跑 `npm run db:seed`，不要跑 `db:seed:demo`**（那是假資料）。
   接著用 `scripts/create-admin.ts` 建正式管理員，不要沿用 seed 的預設密碼。
7. **建備份**：磁碟快照排程 ＋ Cloud Storage 同步 ＋ **同步一份到診所 NAS**。
8. **驗一次還原**：照 `06` §三跑一遍 pg_restore。備份沒還原過就不算有備份。

- [ ] 後台登入，班表 21 列都在、國定假日涵蓋到 2027-12-31

- [ ] 立刻改掉 seed 預設密碼，並為管理員開啟兩步驟驗證

## 三、內部試營運（建議至少 1 週）

**這段期間官網完全不動，家長還是用 BookNow。** 只有診所內部知道新網址。

1. 櫃檯用真的流程操作：代約、報到、改期、取消、標記未到、匯出。
2. 院長與櫃檯照 `10-測試與驗收.md` §二逐項打勾。
3. 每天早上看一次月曆總覽，確認當天名單與 BookNow 對得起來。
4. **提醒簡訊**：前一日 20:00 會自動發。第一天請確認真的收到、字句正確、費用計算符合預期（每則壓在 70 字＝1 則）。
5. 有任何一項不對，回報後修好再重跑一次驗收。

> 試營運期間兩套系統並存是刻意的：新系統只有你們在用，出問題不影響家長。

## 四、切換當天

挑**門診較少的一天**（例如週三下午或休診日），不要挑週一。

### 切換前一天

- [ ] 官網公告新的預約方式（可見文字，需院長核可後上架）
- [ ] LINE 官方帳號發一則通知
- [ ] 確認 BookNow 上**未來還有多少筆預約**——這些是要處理的重點，見下

### 當天步驟

1. **把 BookNow 既有預約搬過來**。系統沒有匯入功能，兩種做法擇一：
   - **不搬**：BookNow 保留到最後一筆預約看診完為止，新預約一律走新系統。**建議這個** ——
     最多並存 14 天（BookNow 也是開放 14 天），期間櫃檯兩邊都看，之後自然淨空。
   - **搬**：櫃檯用後台「代客預約」逐筆重建。筆數多會很久，且要重新輸入病人資料。
2. **改官網連結**：把預約按鈕從 `lhpedclinic.booknow.com.tw` 改成 `booking.lhpedclinic.com.tw`。
   **2026-08-09 實際清點：全站共 34 處**，分佈在 6 個檔案——

   | 檔案 | 處數 |
   |---|---|
   | `index.html` | 12 |
   | `visit-guide.html` | 6 |
   | `services/child-development-screening.html` | 5 |
   | `services/wound-care.html` | 3 |
   | `services/skin-conditions.html` | 2 |
   | `services/ent-care.html` | 2 |

   含**可見連結與 FAQ／PropertyValue 結構化資料**兩種，兩邊都要改。
   改完用 `grep -rc "booknow.com.tw" --include=*.html .` 確認歸零（LINE 選單另外在 LINE 後台改）。
3. **改官網公告文字**（`09` §五第 1 點）：
   - 超額行為那句：公告寫「自動取消第 3 筆、不另行通知」，新系統是「當下擋下並說明」→ **必須改寫**
   - 報到逾時：**不改**，維持「即取消」（院長 2026-08-05 裁示）
4. **改 LINE 選單**的預約連結。
5. 跑 `python3 internal/tools/validate_site.py --root . --stage deploy`，ERROR 清零才 push 官網。
6. 自己用手機從官網點一次預約，走完整流程。

### 當天之後一週

- 每天對一次月曆總覽與現場實際到診人數
- 留意有沒有家長反映「收不到簡訊」「查不到預約」
- BookNow 先**不要退訂**，留到確定穩定為止

## 五、出事怎麼退回去

新系統壞掉時，**官網連結改回 BookNow 就等於復原**——BookNow 還在、資料還在。

| 狀況 | 處理 |
|---|---|
| 網站開不起來 | `docker compose restart`；仍不行 → 官網連結改回 BookNow |
| 簡訊發不出去 | 檢查供應商餘額與帳密。家長暫時改用 LINE 或電話預約 |
| 資料異常 | 用當天的 pg_dump 還原（`06` §三）。**先確認要還原到哪個時間點再動手** |
| 完全無法排除 | 官網連結改回 BookNow，新系統下線檢修。已在新系統成立的預約，用月曆總覽印出來，櫃檯人工處理 |

> **BookNow 至少留到切換後一個月**。省那點月費不值得。
